Privacy policy

Bulk Subtasks — last updated 15 September 2026.

Documentation Privacy policy Support

The short version

The app stores nothing. It has no database, no storage permission, and makes no network calls to any server outside Atlassian. No data reaches harvizzle at any point.

What happens when you use it

The text you paste is sent to Jira's own API to create the subtasks, and is then gone. Nothing is written to app storage, because the app has no storage permission to write with — you can confirm this on the app's permissions screen at install time.

Personal data

None is stored. The app never copies, caches or retains an Atlassian account ID, name, email address or avatar. Because it holds no personal data, it has nothing to report under Atlassian's Personal Data Reporting API and nothing to erase when an account is closed.

Permissions and why they exist

  • Read Jira work — to find the parent issue's project and its subtask issue type.
  • Write Jira work — to create the subtasks.
  • Read Jira user — used only when a project refuses unassigned issues, so the new subtasks can be assigned to you.

Every action runs as the signed-in user, under that user's existing Jira permissions. The app cannot see or do anything you could not already do yourself.

Third parties, analytics and tracking

There are none. No analytics, no trackers, no advertising, no third-party services of any kind.

Uninstalling

Removing the app removes the panel. There is no stored data to delete, and subtasks you already created stay in Jira as ordinary issues.
