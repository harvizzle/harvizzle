What it does

Jira has no built-in way to make an issue repeat. Standups, weekly reports, release checklists and monthly reviews get recreated by hand, or cloned from last week's copy.

This app takes an issue that is already set up the way you like and recreates it on a schedule you choose, with all of its subtasks.

Setting it up

There is no setup. Install the app and it appears on every issue.

Making an issue repeat

  1. Open the issue you want to repeat.
  2. In the Details sidebar on the right, expand Repeat.
  3. Choose how often: every day, every weekday, every week on a chosen day, or every month on a chosen date.
  4. Choose the hour, and the timezone. The timezone is filled in from your own Jira profile.
  5. Click Start repeating.

Each copy is created with the original's summary, description, issue type, priority, labels, assignee, and every subtask with its own summary, description and assignee.

Managing repeats

Go to Apps → Recurring Issues to see every repeat on the site, when each one next runs, and what it last created. Any repeat can be paused and resumed, or deleted. Repeats are shared across the site.

When it runs

The app checks once an hour. A repeat set for 09:00 is created during the 09:00 hour in the timezone you chose, not necessarily on the exact minute — Atlassian spreads scheduled work across the hour.

Creating a repeat never creates an issue immediately. If you set up a 09:00 daily repeat at 09:30, the first copy appears the following day.

Timezones, daylight saving and month ends

Schedules are evaluated in the timezone you picked, so they do not drift when the clocks change.

  • On the day the clocks go back, an hour occurs twice locally. A repeat set for that hour runs once, not twice.
  • On the day the clocks go forward, an hour does not exist locally. A repeat set for that hour is skipped for that day rather than firing at the wrong time, and resumes normally the next day.
  • A monthly repeat set for the 29th, 30th or 31st runs on the last day of shorter months, rather than silently skipping them.

Missed runs

If a run is missed — an outage, or the app being reinstalled — the app creates one catch-up issue rather than one for every missed slot, so a quiet period does not flood your backlog.

Who the issues are created by

Scheduled work in Jira runs without a signed-in person, so each recurring issue is created by the app itself. The Reporter on the created issue is shown as Simple Recurring Issues. The assignee is copied from the original issue.

What this version does and does not do

Included: summary, description, issue type, priority, labels, assignee, and subtasks with their own summaries, descriptions and assignees. Pause, resume and delete.

Not included yet: custom fields, attachments, comments, linked issues, components, fix versions, repeats that stop after a set number of runs, and repeats on a specific minute. These are on the roadmap. They are listed here so nobody installs the app expecting them.
